# Jev + Simforge closed-loop: established facts (measured this session)

## Jev API contract (from docs.typesafe.ai, read directly)

- Endpoint: `POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer $TYPESAFE_API_KEY`.
- Key is live and saved at `~/.config/typesafe/env` (mode 600), sourced from `~/.bashrc`.
- Request: `{state, model, questions}`.
  - `state`: `string | object | array` — **JSON only. TEXT-ONLY MODEL. NO IMAGE INPUT.** No multimodal
    content parts, no URL refs, no binary. Verified across the full docs index (`llms.txt`), API
    reference, and both SDK type surfaces. `ModelCard` has only `name`/`description`/`release_date`
    (no modality field).
  - `questions`: map of id -> question. Three types only:
    - `noul`: yes/no -> returns `noul` in [0,1]. No confidence field.
    - `choice`: returns `choice` (argmax key), `probabilities` (over YOUR declared option keys, sums to 1), `confidence`.
    - `score`: returns `score` (probability-weighted index over YOUR ordered levels), `legend`, `probabilities`, `confidence`.
- **Jev cannot emit a trajectory, a number, or free text.** It can only distribute probability over an
  answer space the caller declared. Therefore: CODE ENUMERATES CANDIDATE TRAJECTORIES, JEV SELECTS ONE.
  (Their "select instead of generate" pattern; see cookbooks/pre_parsed_value_extraction, function_calling.)
- `confidence` is a derived statistic of distribution concentration, NOT correctness probability.
  Docs: calibration holds "across groups of predictions"; "typed output guarantees the interface, not truth."
- Training: RLCD (reinforcement learning for calibrated decisions). Not RLHF/RLVR. No generated text,
  no chain of thought.
- All questions in one request see the same state, are evaluated INDEPENDENTLY, and cannot see each
  other's answers. Chaining requires a second round trip.
- Pin the model version. `jev-latest` currently resolves to `jev-1.13.0`; a cookbook pins `jev-1.12`.
  Floating `latest` will silently shift eval results.

## Measured latency (12 reps/config, this machine, urllib without connection reuse)

| request                  | min | median | p90 | max | tokens in/out |
|--------------------------|-----|--------|-----|-----|---------------|
| 1 question, tiny state   | 178 | 242    | 275 | 307 | 305 / 22      |
| 2 questions, full scene  | 203 | 229    | 306 | 363 | 854 / 87      |
| 8 questions, full scene  | 150 | 229    | 295 | 308 | 1124 / 229    |

- **Latency is FLAT in question count.** 8 questions == 1 question in wall time. Marginal judgment ~0 ms.
- Batched vs split, same 8 judgments: 301 ms / 1353 tok batched vs 1739 ms / 6363 tok split
  (5.8x faster, 4.7x fewer tokens).
- Transport floor: dns 4.6 ms, connect 35.6 ms, TLS 70.2 ms. So ~70-100 ms of each call is network,
  ~130-160 ms is inference. USE A KEEP-ALIVE / POOLED CLIENT (the official SDKs pool).
- Jitter is the risk: 150..363 ms spread on identical requests (2.4x).
- Practical decision rate: ~3 Hz (300 ms p90 budget). Matches the public "Jevpilot" demo HUD (283 ms).

## Reference design observed in the wild ("Jevpilot" demo screenshot)

Two-rate architecture, confirmed by HUD: `Straight - 99%` (Choice + probability),
`60 km/h target` (Choice over a closed set of legal speeds), `283 ms` (per-request latency),
boxed `65` (speed limit from map), `Turn left in 402 m` (deterministic route planner, not Jev),
blue ribbon (path geometry generated by CODE from lane centerlines), `{} JSON` inspector button.
Decision layer ~3.5 Hz and LATCHED; path tracking runs every frame in local deterministic code.
Note the ribbon already curves left while the decision reads "Straight" -> the path is route-derived,
Jev only picks the discrete maneuver for the current instant.

## Hard constraints for the integration

1. Jev output is ADVISORY into a planner that stays correct when Jev times out, errors, or returns
   garbage. Default on missing answer = current safe behavior, never "proceed".
2. A deterministic safety layer (kinematic limits + collision check + emergency brake) owns actuation
   and can override any Jev selection. Every candidate offered to Jev must ALREADY be feasible+safe,
   so a wrong pick is suboptimal, never illegal.
3. Prefer stepping the sim on a fixed timestep decoupled from wall clock, so the decision cadence is
   deterministic and evals are reproducible despite network jitter.
4. Simulation only. No public-road actuation.
