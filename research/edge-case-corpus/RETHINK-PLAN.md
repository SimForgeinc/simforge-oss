# PLAN — rethinking scenario generation (lead: Fable agent on path-pc, 2026-08-16)

Companion files: `REVIEW.md` (verified-claims ledger), `OWNER-EDGE-CASES.md` (owner reference list + directives), `CONTRACTS.md` (shared contracts for work streams).

## 1. What I believe the real problem is

**The project has been optimizing a number that is already saturated, against an instrument that does not measure what the owner wants.**

Evidence, all verified first-hand or from raw on-disk reports (see REVIEW.md):

1. **Admission rate is at its ceiling and the ceiling is not the model.** The deterministic no-LLM surface scores DEV 0.7534 / HELDOUT 0.6963; luna through the same representation scores 0.6986 / 0.6222. The LLM adds nothing over the compiler because the compiler owns all behaviour — the LLM fills ~10 scalar fields. Remaining losses are dominated by map inventory (C8/C13/C10: no workzone-suitable corridor, no roundabout, no school zone — 0 sites), which no authoring change can fix.
2. **The gate certifies criticality, portability, and reproducibility — not realism or dynamism.** 34.8% of admitted W7 archetypes fail mechanism provenance; situational plausibility is ~0.93 for admitted *and* rejected scenarios. Nothing in the pipeline measures whether a scene looks like living traffic. The owner's stated want — "swerving, traffic light manipulation, realism, dynamic scenarios" — is exactly the unmeasured dimension.
3. **The representation is dramatically underused, not deficient.** Schema v2 already expresses: up to 64 actors, 256 interactions, signal phase programs and mid-sim `set signal:*.phase` overrides, mid-sim lane changes, metric lateral swerves (`laneOffset`), polyline routes, weather/friction/time-of-day, non-ego reactive triggers (`when` conditions on any actor pair), and engine-native **reactive ambient traffic** with seeded driver diversity that has never been used in any corpus run. The 8 hand-written compilers emit approximately none of this. The owner's asks are expressible *today*.
4. **Two of the negatives motivating the current framing are weaker than stated.** "Vision lost twice": n=32/arm, p=0.187, HELDOUT converged, and a sight-favoring quality subgroup — the defensible claim is only "vision didn't help *admission* in that *repair-loop* design". "Effort buys nothing": zero committed data (W8 results exist only in the Mac's in-flight run). Both matter because they've been used to fence off vision and to argue the authoring surface is the only lever.

**Restated: the bottleneck is (a) an authoring surface that exposes ~3% of the representation, (b) the absence of any realism/dynamism instrument, and (c) map inventory for the blocked categories. Not model, not effort, not the gate's strictness.**

## 2. Where I disagree with the handoff and the seed ideas

- **"Re-attempt the VISTA harness from scratch" — partially reject.** VISTA's setting (exploratory game, win condition, visual state you must perceive to act) is not scenario *authoring* (generative, with a deterministic oracle). Authoring-by-pixels was the weak part of the first attempt and I don't expect it to beat schema-level authoring with engine feedback. What transfers from VISTA is the *judging* side: fuzzy visual verification of a high-dimensional outcome ("does this rollout look like real traffic?") instead of ever-more symbolic checks. That is where vision goes in this plan — and it's also what the owner just mandated (footage review pass).
- **"Hundreds of agents in stages" — adopt with a correction.** Throwing cohorts at the *current* decision-dict pipeline reproduces the ceiling at higher cost (the outgoing thread was right). Scale only pays where output diversity is possible, i.e. after the authoring surface is opened to the full schema. Then a generate-wide → simulate → footage-filter funnel is exactly the right shape, and Codex quota makes the filter cheap.
- **"Every agent is a driver, all reacting" — adopt the engine-native version, reject the literal one.** An LLM per driver per tick is not implementable (no external per-tick control API in the engine; latency × ticks is prohibitive) and mostly unnecessary: the engine already has deterministic reactive drivers with per-actor aggression/headway/reaction diversity. Dense ambient traffic + authored provocations gets emergent negotiation at zero LLM cost. If that shows promise, the follow-up engine work is a per-actor policy hook, not an LLM-in-the-loop.
- **"Admission rate is the headline" (lane briefs) — reject going forward.** The gate stays, frozen, as a *floor* and integrity instrument. The primary metrics for this rethink are (i) a pre-registered dynamism census read from raw traces and (ii) a validated footage-review verdict. New instruments are added *beside* the gate, never by touching it — consistent with the "tighten only" rule.
- **The C8/C13/C4 category failures are not authoring failures and should stop being reported as such.** They are map facts. I will keep them quantified for the map handoff, and the unstructured-space items on the owner's list (gas stations, parking lots, campgrounds) land in the same bucket. Flagged plainly: without new maps or map synthesis, whole rows of the owner's list are unhostable; agent effort spent "authoring around" them produces provenance-No scenarios (that's precisely the 34.8%).

> **Owner amendment (2026-08-16, after plan v1):** the owner explicitly directed a VISTA-based approach be built as well, citing the ARC-AGI-3 result. My partial rejection above is therefore overruled for execution — and honestly, the game formulation answers my own objection: authoring *does* have a win condition (the frozen gate), so the ARC-AGI loop maps more faithfully than I first argued. Stream E (VistaLane) runs the faithful re-attempt: visual observation as primary channel, predict/verify per action, lossless frame memory with inspect/read_pixels-as-semantic-query, GUIDE.md/WORKING.md, minimal prompt, gate-as-win-condition, gpt-5.6-sol (the paper's own Codex backend). Head-to-head on the same brief sample against the compiler baseline and the text-schema freedom arm, same instruments. Owner also directed sweeping gpt-5.6 models × efforts in authoring and judging arms.

## 3. Work streams

Five parallel streams, each owned by one omp Fable agent, reporting to me. Shared contracts in `CONTRACTS.md` (briefs sample, artifact layout, verdict schema, metric definitions, model policy, gate discipline). Stream E was added by owner amendment (see §2).

### Stream A — FreeformLane: full-schema agentic authoring
**Hypothesis:** an agent authoring raw ScenarioTemplateV2 (schema-validated, engine-feedback loop, 2–3 repair rounds) produces scenarios that (i) pass the frozen gate at a usable floor (≥0.35 of briefs) and (ii) beat the compiler pipeline on the dynamism census and on footage-judged realism, because it can use the 97% of the vocabulary the compilers ignore (multi-actor triggers, signal programs, swerves, ambient traffic, weather).
**Design:** fixed stratified sample (30 DEV briefs + 20 hostable owner-list scenarios, drawn once, seeded, committed before any run). Baseline arm = existing `author_llm.py` compiler pipeline on the same sample. Freedom arm = new authoring harness giving the model the schema + site-inventory facts + physics facts, emitting full templates. Same gate, same census, same judge on both arms.
**Falsifiers:** template validity <50% after repairs; dynamism census not better than compiler arm; footage realism judged worse than compiler arm; gate floor missed. Any of these measured honestly kills or reshapes the stream — a clean negative here would be the strongest possible defence of the compiler approach, and is publishable as such.

### Stream B — FootageLane: footage review at scale (owner mandate)
**Hypothesis:** a codex-vision judge watching rendered rollouts can (i) reliably separate physically absurd scenes from good ones, and (ii) produce a realism signal that discriminates *within* gate-admitted scenarios — giving the project its first realism instrument.
**Design:** first make `render-trace.mjs` consumable at scale (map/lane underlay from topology so the judge sees roads, not just boxes on a grid — coordinate with Stream D); then **calibrate the judge before trusting it**: a labelled set of known-good cells (gold corpus) vs known-absurd cells (VRU-inside-occluder 0.0 m-separation baseline-arm cells, spawn-artifact cells, frozen-ego cells — all reproducible from committed probes). Report separation (AUC). Only a judge that separates calibration classes gets used. Then run the full W7 corpus + Stream A/C outputs through it; measure inter-model agreement (luna/sol/terra), cost per cell.
**Vision discipline:** `assert_vision.py` per model per session; Anthropic models never touch an image path (verified blind through the gateway on this machine).
**Falsifiers:** judge cannot separate calibration classes (footage review as ceremony — report and stop); inter-model agreement near chance; judge verdicts uncorrelated with the deterministic absurdity markers it was calibrated on.

### Stream C — EmergentLane: ambient traffic and emergent conflict
**Hypothesis:** (i) adding engine-native ambient traffic to existing scenarios raises realism (footage-judged) without breaking gate admission or determinism; (ii) conflicts can be *harvested* rather than authored — dense, aggressive-profile ambient traffic at junction/merge sites, swept over seeds, organically produces gate-passing critical cells at a competitive cost per admitted cell, with mechanisms (negotiation failures, hesitation, cut-ins) that scripted templates never produce.
**Design:** (i) paired arms: N admitted W7 templates re-run with ambient on/off, same seeds — gate survival, dynamism census, footage delta. (ii) harvest arm: no scripted challenger; ambient density/aggression swept at conflict-prone sites; measure organic criticality yield per 1000 cells and *what kinds* of conflicts emerge. Owner-list items this can reach: four-way-stop hesitation, zipper merge, unprotected left across dense traffic, signal blackout (dark-fallback semantics already in the engine).
**Falsifiers:** ambient breaks replay determinism (bit-compare); gate C5 rejects everything from ambient-actor contacts; harvest yield ≈0 or produces only trivial rear-ends; footage judge scores ambient scenes *less* realistic (possible: 20 identical sedans may look less alive than an empty road — that would be a real finding about the actor catalog, feeding Stream D).

### Stream D — EngineLane: base-repo capability and throughput (owner standing order)
Not hypothesis-driven; demand-driven from A–C plus the owner's list. Ordered backlog:
1. **Renderer**: lane/junction underlay in `render-trace.mjs` (topology polylines), throughput for thousands of cells (B's dependency); qualify the Studio/Three 3D path on this RTX 5080 (headed Chrome) as a second-fidelity tier.
2. **Simulation waste**: 30.3% of engine time is `unknown_site` refusals — pre-resolve site validity before spawning cells (measured fix, not a check).
3. **Actor/prop vocabulary for the owner's list**: animal, debris (tire/mattress/ladder), shopping cart, delivery robot, emergency vehicle with light state; reversing behaviour; each added generally (schema + materializer + engine + test).
4. Per-actor policy hook design note (if C shows emergent promise): the seam is `controllers.ts` slot ownership — proposal only, no speculative implementation.
Every change: failing test first, general (never per-scenario), `pnpm -r typecheck` + affected package tests green, tripwire green. Nothing lands that A–C don't need or the owner didn't name.

### Stream E — VistaLane: VISTA-faithful visual authoring (owner amendment)
**Hypothesis:** the paper's loop (visual observation → free-form predict/verify reasoning → act, with lossless frame memory, GUIDE/WORKING notes, minimal prompt, gate-as-win-condition) authors admissible scenarios and *discovers the engine's physics by interaction* — the C2 warm-up trap, clearance geometry, TTC demand — without being pre-taught, the way VISTA discovers game rules. Its GUIDE.md after N briefs is itself a deliverable.
**Design:** minimal harness in `tools/research/vista2/` (≤8 actions: view_site, place_actor-by-pixel→logical-anchor projection, set_motion, simulate→rollout keyframes+per-criterion verdict, inspect, read_pixels-as-semantic-ground-truth, emit). `gpt-5.6-sol` (the paper's Codex backend), vision-asserted. Same brief sample, gate, census, judge as A — a clean three-way: compiler vs text-schema freedom vs visual closed-loop.
**Falsifiers:** cannot beat the text-schema arm on admission or judged realism/dynamism at <5× cost; GUIDE.md never converges on true physics (confabulated rules that don't predict); pixel→anchor projection cannot keep templates portable.

## 4. What would tell me the whole framing is wrong

- If Stream A's freedom arm loses to the compiler on *every* axis (validity, gate floor, dynamism, judged realism), then authoring freedom is not the lever, and the honest conclusion is that this domain genuinely wants hand-built mechanism compilers plus map investment — i.e. the current approach was right and the owner's thesis fails on this engine. That result must be reported as plainly as a win.
- If Stream B's judge cannot separate obviously-absurd from good footage, then "agents review the footage" is not currently viable at any scale, and realism has to come from deterministic instruments instead (census-style), until the render or the models improve.
- If Stream C's harvest yields nothing and ambient adds nothing judged or measured, then "emergence" on this engine is a dead end and scripted choreography is the only path — meaning the owner's game-like formulation needs a different engine (policy hooks or an external sim), which becomes a costed proposal, not a lane.
