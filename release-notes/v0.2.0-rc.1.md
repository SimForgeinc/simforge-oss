# simforge 0.2.0-rc.1

The first release candidate of the Rust `simforge` CLI: it imports scenario
packages exported from the SimForge hosted app, fetches the map releases and
actor models they name by digest, renders them with the deterministic renderer
(`training` and `showcase` presets, camera passes, lidar, radar, video),
re-simulates them, and serves closed-loop episodes to a policy over a socket.
It also ships the authoring commands and agent skills for Claude Code, Codex
and other agents. This is a pre-release: try it, and report problems as issues.

## Install

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/SimForgeinc/simforge-sdk/releases/download/v0.2.0-rc.1/simforge-installer.sh | sh
simforge assets pull --only sky
simforge doctor
```

Windows (PowerShell):

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/SimForgeinc/simforge-sdk/releases/download/v0.2.0-rc.1/simforge-installer.ps1 | iex"
```

Container (CPU with Mesa lavapipe; NVIDIA with `--runtime nvidia -e NVIDIA_VISIBLE_DEVICES=all`):

```sh
docker run --rm ghcr.io/simforgeinc/simforge:0.2.0-rc.1 --help
```

The Python wheels (`simforge-oss-gym` and its siblings) for this candidate are
attached below; PyPI, Homebrew and the `latest` tags follow the stable 0.2.0.
Agents: `simforge skills install --claude` (or `--codex`).

## Verify

Every asset is signed keyless with Sigstore by this repository's release
workflow and has a GitHub build-provenance attestation:

```sh
cosign verify-blob --bundle simforge-x86_64-unknown-linux-gnu.tar.xz.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/SimForgeinc/simforge-sdk/\.github/workflows/release-(sign|container)\.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  simforge-x86_64-unknown-linux-gnu.tar.xz
gh attestation verify simforge-x86_64-unknown-linux-gnu.tar.xz --repo SimForgeinc/simforge-sdk
```

macOS binaries are ad-hoc signed and Windows binaries are not Authenticode
signed; the Sigstore signatures and `sha256.sum` are the integrity check.
SBOMs (CycloneDX) for the binary, the native wheels and the container image
are attached.
