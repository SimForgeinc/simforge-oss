# simforge 0.2.0-rc.0 (DRY RUN, not published)

Status: dry run of the release pipeline on path-pc, 2026-09-26. Nothing was
tagged, pushed, signed publicly or published. Source: simforge-sdk main
dfd1d6b0 (after #39, #58, #61, #62, #63) plus the rebased release pipeline (#24) and
the dry-run version bumps, on local branch `dry/v0.2.0-rc.0`.

The first release of the Rust `simforge` CLI: scenario packages
(`simforge.scenario-package/v1`) exported from the hosted app, maps and actor
assets by digest, the deterministic renderer (training and showcase presets),
re-simulation, closed-loop episodes over a socket, the authoring commands, and
agent skills for Claude Code, Codex and other agents. Engine 0.12.1.

## Blockers before a real release

1. The rc CLI cannot read the smoke package: its `producer.minCli` is 0.2.0
   and semver orders 0.2.0-rc.0 before 0.2.0, so every rc.N refuses it
   (`package_version_unsupported` / `version_ahead`, exit 2). Choose: tag v0.2.0
   directly, or re-export the fixture with minCli 0.2.0-rc.0 (owner P).
2. Land the rebased release pipeline (#24) with the fixes this dry run found:
   `[profile.dist]` in the root Cargo.toml; `publish = false` on `simforge` and
   `simforge-authoring`; the gym's `python-packages` (sdist failed); maturin
   builds without `--release` so `profile = "wheel"` applies; notices licence
   names unescaped; the skills checker accepts `simforge help`; the recorded
   golden and the smoke rig (fixtures/scenario-package/smoke/chase.rig.json).
3. Release binaries consult and print the BUILD machine's source path for sky
   assets (`<checkout>/renderer/render-core/assets/sky`): a path leak, and a
   lookup that can only miss on a user's machine. Owner: C / renderer.
4. Keyless signing, provenance attestations and the macOS/Windows builds run
   only on GitHub Actions: unproven until the first tag run.
5. Accounts: PyPI trusted publishers for the five projects (repo simforge-sdk,
   workflow promote.yml, environment pypi) are not registered;
   simforge-oss-timeline is not yet claimed; crates.io `simforge` is not claimed
   (the account needs a verified email).
